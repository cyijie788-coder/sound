# 奕起聊车视频制作

把用户已经确认的内容做成可观看的成片，并留下能复核的检查结果。质量优先；催促时减少无关探索、复用已验证资产，不能跳过已发现问题或用反复倒计时安抚用户。

## 先确定本轮范围

读取工程 `AGENTS.md`、最新交付记录和当前指令。核对用户正在看的实际文件，不能只凭文件名或聊天中的“第几版”推定基准。

- 只做前期规划：交付完整的逐句分镜或样板预览，不自动渲染整片。
- 用户授权直接制作：利用现有录音和素材推进，不重复询问已经确定的事项。
- 定点修改：读取 [qa-and-repairs.md](references/qa-and-repairs.md)，只改目标及必要的关联轨道。
- 新片或较大改版：读取 [production.md](references/production.md)；具体车型、颜色、画幅、音乐版本、图片时长、结尾和语速属于单片配置。
- 接续本用户项目时参照 [yiqi-preferences.md](references/yiqi-preferences.md)。当前明确指令优先，不能把 M4、RS7 的局部选择变成所有视频的固定模板。

## 制作流程

1. **整理输入和参考用途。** 核实本地文件及实际媒体参数；`.url` 是链接文件，不是可剪辑视频。记录每条参考用于开场话术、镜头节奏、逐字字幕、动效还是 BGM。实际查看后再说“参考了”。
2. **锁定口播，按句排镜。** 以已批准台词和录音为准；ASR 只辅助对齐，核对车名、发动机代号、数字。用户要求先看分镜时给完整时间轴。提速、插段和删段使用统一时间映射，联动字幕、画面、音效和片尾。
3. **清理素材内部切点。** 记录来源、实际像素、车型与版本、原片入出点、重复区间、水印和许可。选材以质量为先，检查所选区间首尾和内部切镜；不能把带有三个机位的素材当成一个连续镜头。处理转场延长区间时也检查源素材会不会进入下一镜。
4. **剪辑、字幕与动效。** 统一 60 fps；原生 4K 选材和输出分辨率分别核对。主体、文字和过冲保持当前安全区；强重点应来自选材、信息落点和节奏反差。逐字字幕按说话时间出现并保留稳定布局，阅读阶段收稳；参数图对应车型版本，真实车图不挤压变形。应用动画十二法则中适合表达的部分，不堆叠闪屏。
5. **声音后期。** 分开保留人声、BGM、音效。使用现成录音或用户指定音频，音效匹配动作或话语；不使用音乐/音效生成器。先查现有 `sound` 工具和素材来源再决定是否下载。配乐有能量但让位于人声，改善空旷感不靠追加混响；具体版本、引擎类型、落点和尾音逐项核对。
6. **实际导出验收。** 按 [qa-and-repairs.md](references/qa-and-repairs.md) 检查导出文件。帧率正确、解码成功、峰值通过，都不能代替画面和听感判断。尤其排查源素材短镜头、旧文字残层和上一镜残留。
7. **交付。** 核实目标文件存在、复制校验一致、链接指向最终版；保留必要来源/署名。样板默认只预览，正式视频/封面按用户要求保存。保留旧版，不因旧版被用户移动而阻断已验证的新文件交付。GitHub 上传只在获得相应授权时执行，不连带上传原声、第三方媒体、凭据或缓存。

## 不可省略的返修判断

- 用户指出“一闪而过”，优先检查实际源切点和截取边界，不先加淡化、冻结或噪声掩盖。
- 将成片的实际场景切点与工程镜头边界一起检查：擦除转场可能掩盖新素材开头夹带的另一个镜头。
- 短于约 0.5 秒的片段先标为复核候选，判断是不是残留、刻意快切或正常转场；不是机械删除所有短片段。
- 从干净区间重新取材，必要时小幅变速或换连续镜头补足原时长；检查结束位置及转场余量，避免刚删掉头部又露出尾部下一镜。
- 对用户标出的切点检查连续每帧、前后衔接，并在可播放环境正常速度复核。只有抽帧、检测或视觉检查时如实说明，不声称完整试听或实体手机播放。

## 可执行的短镜头检查

依赖 Python 3 标准库、可用的 FFmpeg 和 FFprobe；可通过参数传入已核实的二进制路径。脚本只读媒体，写报告及可选检查图，不改视频。

```bash
python3 scripts/audit_short_shots.py final.mp4 \
  --timeline timeline.json --report /tmp/short-shot-report.json \
  --focus 21 --focus 50.75 --review-dir /tmp/shot-review
```

时间轴格式、阈值、证据范围与使用限制见 [qa-and-repairs.md](references/qa-and-repairs.md)。没有候选只表示本次算法未检出，不能直接标成“成片全部通过”。

## 进度与复盘

先检查真实进程和输出，再回答“还要多久”。按剩余渲染帧数、已观测速度、编码/封装和复核工作估区间；耗时未知时说明当前阶段，别连续给没有依据的“再一分钟”。导出完成与验收完成分别报告。已发现问题优先修复，技术报告与用户感受冲突时回到实际画面。

历史漏检的原因及已验证修复方式见 [retrospective-2026-11-14.md](references/retrospective-2026-11-14.md)。这是经验与证据边界，不是对以后每次制作的通过证明。
