# 成片检查与定点返修

## 三类证据分开

1. **技术完整性**：完整解码、实际尺寸/fps、PTS 连续性、总时长、音轨、响度和峰值。
2. **画面检查**：实际导出中连续帧、源切点、文字/水印区域、转场余量和手机尺寸布局。
3. **感知检查**：连续播放、真实听感、实体手机播放。只记录确实做过的项目；无法完成时说明限制。

没有报错、没有冻结或没有候选，都不等于通过全部检查。静止参数阅读阶段可以正常停留；24/30 fps 原片转换到 60 fps 的重复帧不自动算卡顿。检测工具给候选，内容判断决定处置。

## 为什么要同时读源切点和工程切点

实际见过两类漏检：

- A → B → C，B 只出现数帧。只找 A → B → A 的闪屏算法完全漏掉 B。
- 工程擦除转场进入素材，素材开头含 B，随后转 C。单纯场景检测可能没把擦除开始当切点，误以为 B 前面有很长时间。

因此扫描实际画面变化、加入时间轴镜头起止，标记二者之间过短的区间。再看相邻帧决定是碎镜、正常转场还是同一镜头跨两个工程片段。不能直接将所有短候选删除。

## 工具用法

`scripts/audit_short_shots.py` 需要 FFmpeg、FFprobe 和 Python 3，无额外 Python 包。

```bash
python3 scripts/audit_short_shots.py final.mp4 \
  --ffmpeg /absolute/path/to/ffmpeg \
  --ffprobe /absolute/path/to/ffprobe \
  --timeline timeline.json --report /tmp/report.json \
  --focus 21 --focus 50.75 --context 0.35 --review-dir /tmp/review
```

时间轴 JSON：`fps` 是工程帧率，`from` 包含、`to` 不包含；时间使用原始导出起点。例：

```json
{"fps":60,"shots":[{"id":"shot-a","from":0,"to":1262},{"id":"shot-b","from":1262,"to":1401}]}
```

可传 `--scene-threshold 0.28 --min-shot-seconds 0.55` 调整灵敏度。这些是本例经验起点，不是电影镜头的通用下限。

脚本输出视频信息、实际场景切点、与工程边界合并后的短区间，以及 `requires_visual_review` 状态。`--focus` 可重复，会把指定时刻前后的连续帧输出成网格图；图按行从左到右，第一帧和每帧时间间隔写入报告。关注点应覆盖真正切点，而不只是用户四舍五入后的秒数。

默认退出 0 仅表示运行成功；`--fail-on-candidates` 会在有候选时返回 2，工具失败返回 1。没有“自动验收通过”状态。脚本不检查所有同步、声音、修补、字体问题，不覆盖连续播放。VFR 素材的近似帧索引有警告；必须先结合实际 PTS 检查，不能把估算帧号当作精确原始帧号。

## 定点修复

1. 确认反馈基准版，定位台词和问题前后约 1–2 秒。连续取帧并检查原片，找出短片段准确首尾。
2. 保持已批准音频、总时长和字幕时，重选干净镜头填同一窗口；可以小幅改变画面速度。不要用静帧、循环或黑帧隐藏切点。
3. 计算实际可用源区间：`取帧起点 + 输出时长 × 画面速度 + 转场所需余量`，不能越过不需要的源切点。源帧率、工程帧率和导出 fps 分开记录，必要时用秒换算。不能只裁开头而漏查尾部。
4. 需改变整片时间时，用同一分段映射更新所有轨道；语音变速保持音调，核对停顿和首尾音节。
5. 修旧文字/重影时排查实际被挂载的组件与条件范围，移除重复绘制，不能只在新图上盖底色。
6. 渲染受影响片段确认，再导出最终版。对用户问题切点逐帧复核和连续播放，对全片再做短镜头扫描；逐个记录候选理由及处置。已发现问题必须修复或明确交付限制。

## 检查记录示例

每轮记录基准哈希、反馈秒数、旧/新时间对应、修改的源区间/组件、音轨是否变化、导出哈希，以及：

- `technical`: 实际运行的检查和结果。
- `visual`: 连续帧范围、截图/播放证据与处理结论。
- `audio`: 测量、轨道比较、试听分别记录。
- `candidate_decisions`: 短片段的确认异常/正常转场/待定及原因；待定不能算通过。
- `unresolved`: 仍未解决的项，不能默默清空。

最终文件复制后重新核对 SHA256 和路径，再给可播放入口；旧版不见了先判断是否被用户移动，不要因备份检查失败反复重做已验证成片。
